# Глосарій предметної області

Джерела: погоджені рішення [idea.md](idea.md), [questions.md](questions.md) та межі версії [scope.md](scope.md). Визначення використовуються в SRS, тікетах, тестах, коді та документації в одному значенні. Канонічною є назва в першому стовпці; пояснення синонімів не вводять додаткових сутностей або статусів. Глосарій не визначає структуру коду чи бази даних.

## Учасники та основні сутності

| Канонічна назва | Визначення в цьому проєкті |
| --- | --- |
| Салон краси | Один салон за однією адресою, для якого ведуться послуги, майстри, графіки та записи. |
| Клієнт | Особа, яка записується на послуги салону. Створення власного запису потребує реєстрації та входу; адміністратор створює запис від імені зареєстрованого клієнта. |
| Адміністратор | Користувач з окремою роллю для керування послугами, майстрами, їхніми графіками та записами клієнтів. |
| Майстер | Фахівець салону, який виконує визначений адміністратором перелік послуг і має робочий графік. У поточній версії це сутність без власного облікового запису та доступу. |
| Послуга | Пропозиція салону з назвою, описом, актуальною ціною та фіксованою тривалістю, однаковою для всіх майстрів, які її виконують. |
| Каталог послуг | Перелік послуг з їхніми поточними даними, яким керує адміністратор і який можна переглядати без входу. |
| Обліковий запис клієнта | Дані зареєстрованого клієнта для входу за унікальним email і паролем; обов'язкові дані профілю — ім'я, телефон та email. |
| Особистий кабінет | Доступна після входу частина системи для перегляду власних актуальних записів, їхніх деталей та історії, а також скасування за погодженими правилами. |
| Запис | Бронювання для одного клієнта рівно однієї послуги в одного конкретного майстра на визначені дату й час, із зафіксованими даними послуги та розрахованим завершенням. Успішне створення одразу підтверджує запис. |

## Категорії записів та операції

| Канонічна назва | Визначення в цьому проєкті |
| --- | --- |
| Актуальний запис | Нескасований запис, розрахований час завершення якого ще не настав. Включає запис під час надання послуги. |
| Історичний запис | Запис, який скасовано або розрахований час завершення якого вже настав. Відображається в історії та не підлягає редагуванню чи скасуванню. |
| Скасований запис | Запис, скасований клієнтом або адміністратором за погодженими правилами. Зберігається в історії й не займає час ні майстра, ні клієнта. |
| Історія записів | Відокремлений від актуальних записів перелік власних історичних записів клієнта. |
| Створення запису | Успішне збереження бронювання після перевірки доступності та відсутності часових конфліктів. Виконується клієнтом або адміністратором від імені зареєстрованого клієнта. |
| Зміна запису | Редагування адміністратором послуги, майстра, дати або часу актуального запису з повторними перевірками перед збереженням. |
| Перенесення запису | Зміна адміністратором дати або часу запису. Є випадком зміни запису та спричиняє перепланування нагадування за погодженими правилами. |
| Скасування запису | Дія, після якої запис стає скасованим, усі його заплановані нагадування скасовуються, а клієнт отримує email про скасування. |
| Правило скасування за 24 години | Клієнт може самостійно скасувати запис не пізніше ніж за 24 години до початку; за меншого строку звертається до адміністратора. Для адміністратора це часове обмеження не діє. |

У попередніх матеріалах «майбутній запис» використовується в погодженому значенні **актуального запису**, тобто до розрахованого завершення, а не лише до початку. Надалі канонічна назва цієї категорії — «актуальний запис».

«Минулий запис» описує запис, час завершення якого настав; «історичний запис» є ширшим поняттям, оскільки включає також скасований запис із датою в майбутньому. Належність до історії не засвідчує фактичного виконання послуги або явки клієнта. Це категорії для погодженої поведінки, а не вимога до окремих статусів у коді.

## Час, графіки та доступність

| Канонічна назва | Визначення в цьому проєкті |
| --- | --- |
| Часовий слот | Інтервал для запису на обрану послугу до конкретного майстра, визначений моментом початку та тривалістю послуги. Крок можливих початків становить 30 хвилин; це не фіксована тривалість слота. |
| Робочий графік майстра | Повторюваний тижневий розклад робочих інтервалів і вихідних майстра з винятками для конкретних дат, яким керує адміністратор. |
| Робочий інтервал | Проміжок роботи майстра, визначений його графіком для відповідного дня з урахуванням винятків. Уся послуга має вміщуватися в цей проміжок. |
| Виняток графіка | Задана адміністратором відмінність від тижневого графіка для конкретної дати: відпустка, додатковий вихідний або змінений робочий час. |
| Вільний час | Час майстра, в якому обрана послуга повністю вміщується в робочий інтервал і не перетинається з його нескасованими записами. |
| Тривалість послуги | Заданий адміністратором фіксований проміжок часу для послуги, однаковий для всіх майстрів. Для існуючого запису використовується зафіксована в ньому тривалість. |
| Час початку запису | Заплановані дата й час початку послуги в записі. |
| Розрахований час завершення | Час початку запису плюс зафіксована в записі тривалість послуги. Визначає перехід нескасованого запису до історії, а не фактичне завершення роботи. |
| Часовий конфлікт | Перетин часових інтервалів нескасованих записів одного майстра або одного клієнта. Початок наступного запису одразу після завершення попереднього не є перетином. |
| Горизонт бронювання | Максимальна межа вибору часу — до кінця 30-го календарного дня включно. Діє для клієнта й адміністратора, також при перенесенні. |
| Мінімальний строк до початку | Для створення запису клієнтом — 2 години від поточного моменту до початку послуги. Для адміністратора це обмеження не застосовується. |
| Часовий пояс салону | Europe/Kyiv — погоджений часовий пояс роботи системи із часом салону. |

Вільний час майстра сам по собі не означає можливість збереження запису конкретного клієнта: також діють погоджені строки бронювання, відповідність послуги майстру та перевірка конфліктів клієнта. Доступність повторно перевіряється під час збереження. Точну прив'язку 30-хвилинної сітки цей глосарій не встановлює.

## Дані послуги та керування доступністю

| Канонічна назва | Визначення в цьому проєкті |
| --- | --- |
| Актуальна ціна послуги | Поточна ціна послуги в каталозі, виражена в гривнях (UAH). Не є фактом або статусом оплати. |
| Зафіксовані дані послуги | Назва, ціна та тривалість, збережені в записі при його створенні або явній заміні послуги адміністратором. Не оновлюються через зміну каталогу чи зміну лише дати, часу або майстра. |
| Деактивація | Вимкнення послуги або майстра для нових записів зі збереженням наявних записів. Не є фізичним видаленням. |
| Фізичне видалення | Видалення послуги або майстра із системи; блокується за наявності пов'язаних актуальних записів. |

## Сповіщення

| Канонічна назва | Визначення в цьому проєкті |
| --- | --- |
| Email-сповіщення | Повідомлення клієнту електронною поштою про створення, зміну чи скасування запису або нагадування перед його початком. Email є єдиним погодженим каналом сповіщень. |
| Email-підтвердження запису | Email-сповіщення після успішного створення запису клієнтом або адміністратором. Не потребує ручного підтвердження адміністратором і не є підтвердженням email-адреси клієнта. |
| Нагадування | Email-сповіщення про наближення запису, заплановане за 24 години до початку. Якщо запис створено менш ніж за 24 години до початку, окреме нагадування не надсилається. |

Після скасування запису скасовуються всі заплановані нагадування. Після перенесення попереднє нагадування скасовується; нове створюється за 24 години до нового початку, якщо до нього залишається 24 години або більше. За меншого строку надсилається email про зміну без окремого нагадування. Технічна доставка та повторні спроби тут не визначаються.

## Перевірка узгодженості зі scope.md

- Ролі обмежені клієнтом і адміністратором; майстер не отримує власного доступу, а перегляд без входу не утворює нової ролі.
- Запис стосується однієї послуги та конкретного майстра; визначення не додають гостьового бронювання чи автоматичного вибору майстра.
- Актуальні та історичні записи визначені за скасуванням і розрахованим завершенням, без обліку явки, no-show або фактичного виконання.
- Графік, вільний час і часовий конфлікт не додають перерв, буферів між послугами або обліку спільних ресурсів.
- Визначення ціни та зафіксованих даних не додають онлайн-оплати, передоплати чи статусів оплати.
- Email-сповіщення та нагадування відповідають In Scope; нових каналів або інтеграцій немає.
- Відкладені питання з questions.md не закриті визначеннями глосарія. Нових функцій або правил порівняно зі scope.md не додано.
