# Повторний огляд меж реалізації ЛР5

2026-11-01. PLAN-GATE залишається **REVISE** для повного проєкту. NF-обсяг і підготовка G-R4 не оцінені; новий календар і людський GO не вигадані. Умова «перед безумовним запуском повного обсягу» не блокує незалежні функціональні пакети: additional-gates.md §G-R1/G-R4 явно дозволяє їх. Поточне доручення користувача дозволяє готувати реалізацію, TDD і технічні рішення TEST-GATE; остаточний Human Review/Done залишається окремим за workflow.md.

Коригування плану ЛР5: виконувати групи A (доступ, каталог, графік), B (бронювання, конфлікти, історія, зміни), C (email і системне логування), кожну через RED/технічний TEST-GATE/GREEN/REFACTOR. Не закривати D-41/D-44, не заявляти продуктове приймання або закриття G-R2 людиною. Технічний PASS — перевірка агента в рамках прямого доручення, не підроблений Human GO.

D-02–D-06: конкретний пакет уточнень подано користувачу окремим запитанням; до відповіді його залежні випадки BLOCKED. D-07: opaque Bearer сесії без нових TTL/logout/refresh endpoints; SMTP та постійна черга як технічна реалізація наявних email-функцій. Не вводити нових гарантій доставки. D-08–D-10 та NF приймальні пороги залишаються відкритими. Системне логування прямо замовлене поточним дорученням; REQ-F-065 не додається.

Мінімальний стек: Python 3.13 (наявний), Flask 3.1.2 (WSGI, test client, без автоматичної генерації нового контракту), sqlite3 зі стандартної бібліотеки (постійні дані, BEGIN IMMEDIATE для атомарної перевірки і запису), pytest 8.4.2. Валідація JSON за оригінальним OpenAPI через наявний openapi-schema-validator; PyYAML. Паролі — Werkzeug scrypt; токени випадкові, у БД тільки SHA-256 токена. Залежності ізольовані в /tmp та фіксуються lock-файлом. SQLite підходить одному навчальному салону, не є твердженням про досягнення NF-продуктивності.

Перед RED створено лише інфраструктуру Flask factory/SQLite та runner доказів. Початковий HTTP 404 на відсутніх маршрутах є спостережуваною відсутністю функції; імпорт/конфігураційні помилки не приймаються як RED. На кожному наступному етапі окремий Git-коміт. Старі baseline, OpenAPI і рішення Gates не переписуються.
