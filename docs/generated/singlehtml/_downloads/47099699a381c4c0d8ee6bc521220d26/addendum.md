# Уточнення та пропозиції адендуму

Статус усіх рішень нижче: **проєкт / потребує людського погодження**, не затверджені нові REQ. Baseline не змінена. Повні джерела: [SPEC-GATE](../../logs/spec-gate.md), [декомпозиція](../lab3/decomposition-draft.md), [PLAN-GATE REVISE](../lab3/plan-gate.md).

| Питання | Підстава / попередня задача | Рішення лабораторної |
| --- | --- | --- |
| Поточний день є першим із 30? | REQ-F-021, OBS-01, D-02 / #3 | Не обрано; точна остання дата не тестується як погоджена |
| Прив’язка сітки 30 хв, початок рівно зараз для адміністратора | REQ-F-018/020, OBS-04, D-03 / #4 | Не обрано; приклади не затверджують прив’язку |
| Перенесення на 48 год після створення менш ніж за добу | REQ-F-059/060/063, OBS-02, D-04 / #5 | Пріоритет правил відкритий; доставки листів немає |
| Несумісна послуга/майстер при PATCH | REQ-F-012/039/040/043, OBS-03, D-05 / #6 | Пропозиція 422 без збереження; не новий затверджений AC |
| Історія після фізичного видалення; зміна з неактивними сутностями | REQ-F-031/041/053–055, D-06 / #7 | Блокування видалення за актуальних записів визначене; решта відкладена |
| Деталізація доступу й email | D-07 / #8 | Bearer та Session — транспортний проєкт; TTL, logout, refresh, email verification, reset password, retry не додано |
| Критерії NF | D-08–D-10, OBS-05 | Статуси збережено; mock не доводить безпеку, SLA чи продуктивність |
| Як адміністратор знаходить ID зареєстрованого клієнта? | REQ-F-013 | ID передається як вхідна передумова; пошук клієнтів не має явної вимоги, окремий endpoint не додано |
| Видимість деактивованих у каталозі | REQ-F-054/055 | Пропозиція показувати active та забороняти новий запис; остаточну політику показу погодити |
| Формати даних | REQ-F-002/005/017/045/048/049 | Пропозиції: непрозорі string ID, RFC3339, хвилини integer >0, ціна >=0 із кроком 0.01, email format, непорожній телефон без національного regex; не нормативні AC |
| Семантика PATCH графіка | REQ-F-048/049/050 | Пропозиція заміни weekly/exceptions цілком; уникнення дублікатів дат і суперечності kind/day перевірятиме майбутня реалізація |

REQ-F-056–064 покриті лише зв’язком із тригерами та описом побічних ефектів; окремий REST endpoint для email не потрібен. REQ-F-028 потребуватиме справжнього конкурентного тесту майбутньої реалізації. 11 NF залишаються в матриці як непридатні для підтвердження цим mock. Наявність x-requirement-ids не означає виконання вимоги.

Пропозиція подальшого погодження: розглянути ці питання в чинних D-02–D-10, не дублювати їх новими вигаданими REQ-ID. API-GATE лабораторної оцінює контракт/mock; його GO не закриває PLAN-GATE чи приймання продукту.
