# ЛР6 — матеріали людської валідації

Початковий задум у [`spec/idea.md`](../spec/idea.md) описує онлайн-запис одного салону: публічний каталог, майстрів і вільні слоти, облікові записи клієнтів, створення/скасування/перегляд записів, адміністративне керування та email-повідомлення. SRS і SKED уточнюють правила ролей, Europe/Kyiv, графік, конфлікти, 24 години та 30 днів. Лабораторна №5 реалізує дозволений скорочений модуль Bookings і його залежності; це не автоматична зміна SRS.

| Початкова потреба | Реалізована можливість | Спосіб ручної перевірки | Фактичний результат | Обмеження | Висновок |
| --- | --- | --- | --- | --- | --- |
| Перегляд послуг | `GET /services` без входу | Запустити `serve`, виконати `curl -i http://127.0.0.1:8000/services` | 200, список послуг | API без UI | Підтверджено для API |

## Короткі дії для самостійної перевірки

1. Створіть середовище й залежності: `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements-lock.txt`, `.venv/bin/python -m pip install -r requirements-docs.txt`.
2. Перевірте CLI: `.venv/bin/python -m salon --help`.
3. Запустіть сервер: `.venv/bin/python -m salon --database /tmp/salon-human.sqlite3 serve --host 127.0.0.1 --port 8000`.
4. У другому терміналі виконайте `curl -i http://127.0.0.1:8000/services`, `curl -i http://127.0.0.1:8000/masters` і `curl -i http://127.0.0.1:8000/`; останній запит демонструє відсутність UI.
5. Для повного client/admin сценарію використайте JSON і послідовність із [`docs/user-guide.md`](user-guide.md); збережіть HTTP-коди та тіла відповідей.
6. Для пошти задайте `SALON_SMTP_HOST` і `SALON_SMTP_SENDER` на локальний sink та запустіть `.venv/bin/python -m salon --database /tmp/salon-human.sqlite3 worker --once`.

Під час ручної валідації підтверджено прийнятність API/CLI як фактичного інтерфейсу погодженої лабораторної. Відсутність UI та `listSlots` не включено до цього підтвердженого обсягу; вони залишаються окремими рішеннями наступного SDD-циклу. Результат не підміняється автоматичними тестами.

## Зафіксований результат

Ручну валідацію підтверджено для дозволеного викладачем обсягу лабораторної №5: реалізований API-модуль Bookings разом із необхідними залежностями каталогу, auth, графіка, SQLite та outbox. Позитивні результати таблиці означають прийняття фактичної поведінки API/CLI в цьому обсязі; `listSlots`, графічний UI та незакриті нефункціональні вимоги залишаються поза підтвердженим обсягом і передаються до наступного SDD-циклу. Це підтвердження не є прийманням усієї SRS.
