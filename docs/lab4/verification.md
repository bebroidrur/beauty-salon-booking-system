Середовище: Python 3.13.0, Node 22.16.0, npm 10.9.2. Залежності встановлено у /tmp без зміни глобального середовища; точні версії зафіксовано в requirements-lock.txt і package-lock.json. Початкові мережеві звернення та bind/HTTP були заблоковані sandbox (ENOTFOUND/EPERM); після дозволеного запуску поза sandbox інструменти доступні, кінцевого блокера немає.

Під час підготовки виправлено порожні required у PATCH-схемах (невалідно для OAS 3.0), регістр HTTP-заголовків у runner, розпізнавання заголовка матриці та узгодженість прикладу PATCH із його запитом. Негативні запити фактично повернули оголошену ApiError, тому runner перевіряє її, а не припускає власний diagnostic формат Prism. Кінцеві журнали належать повторному запуску після виправлень.

**API-GATE: GO — для навчального проєкту контракту й mock API.** Жоден із десяти критеріїв у межах цієї лабораторної не заблокований. Це не дозвіл на реалізацію спірних правил і не приймання продукту. Попередній PLAN-GATE залишається REVISE; D-02–D-10 та питання [адендуму](addendum.md) не закриті цим рішенням. Погодження людиною не заявляється.

Примусове отримання 409/422 не доводить, що mock обчислив конфлікт, часову межу або доставив email. Статичні приклади є незалежними знімками: POST/PATCH не змінюють результат наступного GET. Після перезапуску в інший день часові приклади лишаються ілюстраціями, не перевірками актуальної доступності.

Команди запуску, перевірки й ручні curl: [README](README.md). Для завершення лабораторного оформлення залишаються людський перегляд контракту/чернетки звіту; коміти дозволені фінальним дорученням за [планом](commit-plan.md). Додаткова реалізація до обсягу цієї роботи не входить.

Фінальний аудит і межа перевірки згаданих 17 пунктів: [final-audit.md](final-audit.md). Повторний запуск використовує переносимий npm lock-файл, перевірений чистим npm ci.
