## Контрактні HTTP-перевірки

Для кожної з 18 операцій runner підставляє path/query examples, тіло request example і синтетичний Bearer для захищених операцій. Перебирає **всі 121 оголошені відповіді**: `Prefer: code=<status>, example=<name>` (для 204 без example). Перевіряє фактичний статус, application/json, відповідність OAS30-схемі з format checker і точну рівність прикладу. Для 204 перевіряє відсутність тіла. Це 18 позитивних та 103 негативні відтворення, не 121 перевірка бізнес-умов. Додатково виконуються 18 успішних запитів без Prefer зі звіркою статусу та схеми. Разом 147 HTTP-запитів: 18 типових успіхів + 121 відтворення + 8 відхилень вхідних даних. Після зміни специфікації кількість автоматично перераховується.

| Сценарій | Запит | Очікування | Що реально перевірено |
| --- | --- | --- | --- |
| Каталог | GET /services; GET /masters | 200 ServiceList/MasterList | Маршрути, масиви й поля |
| Реєстрація / вхід | POST /users; POST /sessions | 201 User / 200 Session | Форма відповідей без password |
| Створення / зміна послуги й майстра | POST колекції; PATCH за ID | 201 / 200 | Метод, поля, відповіді |
| Фізичне видалення | DELETE за ID | 204 або 409 | Порожнє тіло / ApiError |
| Графік / слоти | GET, PATCH schedule; GET slots з date/serviceId | 200 / 409 | Схеми, параметри, приклади |
| Список і деталі записів | GET bookings?category=current; GET за ID | 200 / 401 / 403 / 404 | Форма контракту; не фільтрація власника |
| Створення запису | POST /bookings | 201 / 409 / 422 | Booking / TIME_UNAVAILABLE / BOOKING_RULE_VIOLATION |
| Перенесення | PATCH /bookings/{bookingId} | 200 / 403 / 409 | Форма зміни та відмови |
| Скасування | POST /bookings/{bookingId}/cancellation | 200 / 409 / 422 | cancelled/history; HISTORICAL_BOOKING; CANCELLATION_TOO_LATE |

## Реальне відхилення вхідних даних mock без Prefer

| ID у JSON | Негативна умова | Фактичний HTTP |
| --- | --- | --- |
| missing-registration-fields | Порожнє тіло реєстрації | 422 |
| extra-registration-role | Спроба передати role=administrator | 422 |
| invalid-email | Некоректний email при вході | 422 |
| empty-booking-patch | Порожня часткова зміна | 422 |
| invalid-booking-date | startsAt=tomorrow замість date-time | 422 |
| missing-slot-query | Немає serviceId/date | 422 |
| invalid-category | category=completed | 422 |
| missing-auth | Немає Bearer для списку записів | 401 |

У кожній відповіді перевірена ApiError. Prism перевіряє наявність Bearer, не його справжність. Наприклад, 422 BOOKING_RULE_VIOLATION при невалідній даті обрано зі статичного прикладу, це не діагностика реального правила бронювання.

## Сценарії предметної області для наступного етапу

Нижче очікування SRS зіставлені з запропонованим HTTP. **Стан: не виконано як перевірку бізнес-логіки**. Для граничних значень потрібні керований годинник, дані та майбутня реалізація; mock цих компонентів не містить. Де наведено статус — у mock відтворено лише відповідну форму відповіді.
