# Чернетка звіту з лабораторної роботи №4

Дисципліна: «Проєктування інформаційних систем». Тема: «Проєктування REST API за специфікацією». Проєкт: інформаційна система онлайн-запису до салону краси. Дата: 20.10.2026. Автор, група та реквізити титульної сторінки: заповнюються студентом; невідомі дані не вигадано.

## Мета

Спроєктувати REST API відповідно до погодженої SRS, забезпечити простежуваність операцій до вимог і перевірити контракт через автоматичну валідацію та mock API без реалізації сервера, БД і бізнес-логіки.

## Вхідні матеріали

Використано SRS 1.0, 64 функціональні й 11 нефункціональних вимог, 57 критеріїв приймання, 35 BDD-сценаріїв, глосарій, scope, початкову матрицю та SPEC-GATE лабораторної №2. З лабораторної №3 використано декомпозицію, зв’язки D/Issue, реєстр уточнень та PLAN-GATE. Вісім контрольних сум baseline перевірено автоматично. Непогоджені NF не стали затвердженими через проєктування API.

## Хід роботи

1. Проаналізовано джерела й відокремлено погоджену поведінку від відкритих питань. Один салон; ролі клієнта й адміністратора; майстер без акаунта; оплата поза межами.
2. Виділено сім типів REST-ресурсів і 18 операцій на 11 URI. Визначено методи GET/POST/PATCH/DELETE, параметри, авторизацію та коди відповідей.
3. Побудовано OpenAPI 3.0.3 YAML із моделями ресурсів, запитів, відповідей і ApiError. Кожна операція отримала x-requirement-ids із чинними ID.
4. Підготовлено розширену матрицю на 75 вимог зі збереженням AC/GWT та D/Issue. Email-поведінку позначено як побічні ефекти операцій, NF — як неперевірені mock.
5. В ізольованому середовищі встановлено валідатори та Prism. Виконано валідацію специфікації й прикладів, запущено mock зі специфікації та HTTP-сценарії.
6. Зафіксовано результати й API-GATE; підготовлено план трьох комітів; фінальним дорученням їх створення дозволено після аудиту.

## Результати

OpenAPI пройшла автоматичну валідацію. Перевірено 161 приклад, унікальність 18 operationId, посилання на 64 F-вимоги, незмінність восьми baseline-файлів та 75 рядків простежуваності. Prism 5.14.2 успішно запущено локально. Пройшло 147 HTTP-запитів: 18 типових успіхів без Prefer, 121 відтворення оголошених відповідей і 8 відхилень некоректних запитів без примусового вибору статусу. Докази: [протокол](verification.md) та журнали в logs/lab4/.

API-GATE — GO у межах контракту/mock. Відкриті питання горизонту, часової сітки, нагадувань, історії після видалення та NF залишаються у [адендумі](addendum.md). Mock не підтверджує виконання правил 2/24 годин, ролей, власності, конкурентного бронювання або email; такі результати не заявляються.

## Висновок

Створено перевірений контракт REST API з простежуваністю до погодженої SRS та відтворюваним mock-тестуванням. Відокремлено проєктні HTTP-рішення від затверджених вимог і контрактні перевірки від перевірок майбутньої реалізації. Артефакти попередніх лабораторних збережено. Чернетка потребує заповнення авторських реквізитів і людського перегляду перед поданням.
