# Первинна декомпозиція вимог — лабораторна робота №3

**Статус: чернетка для перевірки людиною.** Дата: 2026-10-12. Жоден наведений тікет ще не створено й не виконано. Позначення D-01 тощо — локальні номери пропозицій, не ID вимог і не номери GitHub Issues.

## Джерела та стан baseline

- [SRS 1.0 від 2026-09-29](../../spec/SRS.md) — основа декомпозиції, 64 функціональні та 11 нефункціональних вимог.
- [Глосарій](../../spec/glossary.md) — канонічні терміни.
- [Критерії прийняття](../../spec/acceptance-criteria.md) — 57 AC.
- [BDD / Given–When–Then](../../spec/given-when-then.md) — 35 GWT.
- [Матриця простежуваності](../../spec/traceability-matrix.md) — 75 рядків; Ticket, Test, Code, Documentation поки порожні.
- [Функціональні вимоги](../../spec/functional-requirements.md), [нефункціональні вимоги](../../spec/non-functional-requirements.md), [межі](../../spec/scope.md).
- [SPEC-GATE](../../logs/spec-gate.md) та [незалежний огляд](../../logs/spec-independent-review.txt) — PASS WITH NON-BLOCKING OBSERVATIONS; OBS-01–OBS-05 залишаються відкритими.

Baseline зафіксовано комітом `c860d9580693acd52b92a04104866939945ee78e` (`docs(spec): establish baseline specification`). Фіксація не затверджує всі NF-пропозиції: повністю погоджена REQ-NF-004; REQ-NF-005, REQ-NF-007, REQ-NF-008 мають погоджену загальну основу, але непогоджені конкретні критерії. Решта NF — пропозиції. Їх спочатку винесено на погодження, а не в безумовну реалізацію.

## Правила декомпозиції та SDD

Пропонований порядок: Specification і поточна робоча матриця (D-45) → людський Gate готовності → потрібні для конкретного пакета Addendum → Test (RED) → Feature (локальний GREEN, рефакторинг) → Verification (повний інтеграційний GREEN) → Validation → документація реалізації (D-43) → підсумковий Gate. Це план роботи, а не свідчення проходження етапів.

Згідно з SRS §9.4 автоматизовані тести створюються до коду; текстові журнали тестів і перевірок зберігаються в `/logs` репозиторію. Test закривається після відтворюваного локального RED через відсутню поведінку, а не помилку середовища. Для ізольованих перевірок використовуються контрольні дані й тестові заміни суміжних компонентів; готовий адміністративний інтерфейс для підготовки даних не потрібний. Feature закривається після локального GREEN і регресії реалізованої частини. Це не остаточне приймання всієї вимоги: інтеграційні AC та всі повні Then усіх 35 GWT перевіряє D-40 після завершення залучених Feature. Кожен Test заздалегідь визначає локальні перевірки й перелік інтеграційних перевірок, переданих D-40; сценарії не скорочуються і частковий прогін не позначається повним PASS.

**Семантика залежностей:** «Блокує початок» — потрібно завершити вказані D-тікети до початку локальної роботи; «Блокує локальне закриття» — потрібні результати цих D-тікетів для GREEN; «Умовне блокування» — лише зазначена неоднозначна частина не виконується до рішення людини. «Інтеграція в D-40» — зв’язок перевірки, а не зворотне блокування локального Feature. D-11 затверджує карту дозволених пакетів і заблокованих випадків, не очікує закриття всіх D-02–D-10. Для невизначених випадків відкладення залишає блокування, а не дозволяє AI вибрати поведінку.

Критерії завершення нижче — умови закриття робочих задач, не нові AC специфікації. Наявні AC/GWT перелічено лише за прямими зв'язками матриці. Сценарій із кількома вимогами може повторюватися в різних задачах; це не означає дублювання автоматизованого тесту чи повного покриття кожної вимоги одним сценарієм. Для вимог без AC/GWT тест виводиться безпосередньо з тексту SRS; нові нормативні критерії мовчки не додаються.

Неоднозначності не розв'язуються припущеннями в коді або тестах. Addendum готується окремо від незмінної baseline, з рішенням людини та посиланнями на чинні ID. Відкладені підтвердження email, відновлення пароля, повторні спроби доставки не перетворено на Feature. Не додаються оплата, SMS, кабінет майстра, гостьові записи, облік явки або нові інтеграції.
