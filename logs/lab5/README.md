# ЛР5 — структура доказів

Каталог `logs/` існував до ЛР5. Тут створено окремий простір, попередні докази не перезаписано. Стан продуктового тестування та Gates: **NOT RUN / NOT REVIEWED**. `.gitkeep` лише зберігає порожній каталог, не є доказом перевірки.

| Каталог | Призначення |
| --- | --- |
| `audit/` | Фактичні перевірки цього підготовчого етапу; не TEST-GATE |
| `test-gate/red/` | Майбутній очікуваний збій поведінкового тесту до реалізації |
| `test-gate/green/` | Майбутній успішний запуск після мінімальної реалізації |
| `test-gate/refactor/` | Майбутня регресія після рефакторингу й diff |
| `spec-addendum-gate/` | Майбутня пропозиція, impact/diff, review та рішення людини |
| `final/verification/` | Майбутні перевірки відповідності специфікації |
| `final/validation/` | Майбутнє сценарне приймання людиною |

Для кожного запуску створювати окремий `<run-id>.txt` з timestamp/timezone, HEAD, хешем або diff незакомічених тестів і коду, версіями інструментів, командою/cwd, REQ/AC/GWT/test ID, передумовами/fixture, stdout/stderr, exit code, фактичним результатом і обмеженнями. Приклади імен описують майбутній формат, таких файлів зараз немає. JUnit/coverage лише доповнюють сирий журнал. Дані синтетичні; секрети та персональні дані не комітити.

Для Gate створити окреме рішення з обсягом, переліком доказів і їх хешами, reviewer, датою, критеріями, блокерами та висновком. Не підставляти людину, дату, GO чи PASS до фактичного review. Порожні каталоги не дають права закрити Gate.

Наявні фактичні журнали: `audit/baseline-check.txt` (SHA-256 та нормалізоване зіставлення текстів), `audit/lab3-check.txt` (exit 0), `audit/lab4-static-check.txt` (exit 1: немає yaml). Фінальна перевірка підготовлених документів записується в `audit/document-check.txt`; вона не є фінальною перевіркою продукту.

## Реалізація після початкового аудиту

Початкові NOT RUN вище описують підготовчий етап. За наступним дорученням фактичні цикли збережені у `red/`, `green/`, `refactor/` (шляхи прямо замовлені користувачем). Старі порожні `test-gate/*` залишено для збереження історії плану. `final/verification/` тепер містить реальні перевірки реалізованого піднабору; це не Human validation і не GO всього API. `final/validation/` залишається без вигаданого людського приймання. `spec-addendum-gate/decision.md` містить фактичне рішення **REVISE / NOT APPROVED**, а не GO. `environment/network-sandbox-attempt.txt` — реальні EPERM-падіння bind, не TDD RED; після дозволеного loopback-запуску transport tests пройшли. Усі синтетичні credentials у tests/logs — fixtures, не робочі секрети.
